# Known Limitations

This file records known scope boundaries and verification gaps. A limitation
must not be removed just because it is inconvenient for a progress report.
Update it only when new evidence changes the actual state.

## Data and service

- The included transport dataset is synthetic and fictional. Its Delhi-area
  labels and coordinates do not represent verified real routes, departures,
  fares, or passenger loads.
- The project consumes simplified CSV files, not a GTFS feed. No real-time
  transit API, GPS, live arrival, or service-alert integration is configured.
- The network is small (15 stops, 4 routes, 19 trips). Static sample occupancy
  does not update during a session and may be absent for a trip/stop.
- Public journey search accepts a departure time but not a service date, so
  weekday/weekend service-day constraints are not proven to affect route
  results.
- Map rendering relies on external OpenStreetMap tile availability.

## Routing and passenger experience

- Routing tests now cover the two-minute transfer threshold, delayed
  connection ordering, competing fare/arrival labels, and per-ride-leg fare
  charging on synthetic timetables. Midnight crossing and service-day behavior
  remain unverified.
- Cheapest-route behavior is verified against constructed cases, not an
  independent reference implementation or real transit timetable.
- Input tests cover invalid stop IDs and no-route times, but do not yet cover
  all malformed and out-of-range clock strings.
- Chat is keyword/intent based, not a general language model. It may not
  understand requests outside the listed patterns.
- Browser rendering and complete passenger workflows (search, route selection,
  map, saved-route reopen/delete, delay and crowding display) have not yet been
  exercised in this baseline.

## Fleet simulation

- Fleet data, incidents, responses, and metric values are generated by a
  deterministic demonstration simulator and do not dispatch vehicles.
- Some metrics use fixed scenario assumptions. Their calibration against a
  transport operator or real passenger data has not been established.
- The simulator's multi-bus coordination capability is limited to simplified
  spare deployment and a same-route short-turn scenario; it does not model
  vehicle locations, travel-time reachability, or real dispatch constraints.
- Approval/rejection endpoint responses have API coverage, but they are
  simulated acknowledgements and do not dispatch vehicles or mutate the
  displayed fleet state. Dashboard effects remain unverified in a browser.

## Quality and operations

- Baseline backend tests pass (64 passed, 1 Starlette/httpx deprecation
  warning); frontend type checking and production build pass. This does not
  establish browser usability or a test-coverage percentage.
- Local setup and API operation were verified; production deployment,
  authentication, authorization, managed persistence, backups, monitoring,
  rate limits, and high availability are outside current scope.
- User/session isolation is not implemented. Saved route data is a shared
  local SQLite store.
- The supplied task names DEV-P05 but does not include the organizer's
  canonical problem-statement URL/source document; exact official wording
  remains to be cross-checked.
